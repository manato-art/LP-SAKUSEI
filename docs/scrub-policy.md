# 匿名化ポリシー（scrub policy）

企画書 §5-5 が明文化を要求する「保持リスト / 置換リスト」の正本。
機械可読な実体は `tools/scrub/policy.ts`。本ファイルはその判断根拠を書く。

## 大原則

| | 内容 | 扱い |
|---|---|---|
| **保持（verbatim）** | 画面クローム / i18n文字列 ＝ ラベル・ボタン文言・空状態文・エラー文・バリデーション文言・テーブル見出し | **絶対に触らない**。忠実度の本体はここ |
| **置換** | ユーザー生成コンテンツ ＝ 施策名・beyondページ名・記事メモ・人名・金額/実績値・独自ドメイン・uid/トークン・メール/電話・アップロード物 | 決定論置換 |
| **除去** | 本番JSバンドル参照・外部SaaSタグ・Sentry DSN・inlineイベントの本番URL・meta等の個人情報 | 丸ごと削除 |

過剰scrubは忠実度を殺す。「日本語が架空値に化けたUI」は再現失敗である。

## 精度を出すための設計（重要）

DOM本文だけを見ても「この文字列がラベルか施策名か」は判別できない。
そこで **fixtures(JSON) のフィールド名を文脈として使う**:

1. fixtures を走査し、`title` / `name` / `memo` / `email` 等（`USER_DATA_FIELDS`）の**値**を置換辞書に集める
2. `status` / `role` / `icon_name` / `created_at` 等（`STRUCTURAL_FIELDS`）は辞書に入れない（列挙値を壊すと挙動再現が崩れる）
3. できた辞書の literal を DOM / CSS / HAR にも適用する

この順序により、「実際にユーザーデータとしてAPIが返した文字列」だけが置換され、
UIラベルは巻き込まれない。

補助として:
- 既知の実在社員名リスト（採取係が用意する**非コミット**ファイル。`--names` で渡す）
- パターン置換（メール / 電話 / Bearer / 32文字以上の不透明トークン / ホスト）

3文字未満の値は誤爆防止のため辞書に載せない。

## 参照整合

同じ実値は常に同じ架空値へ写す（`hashString` ベースの決定論生成）。
写像は `scrub-map.json` に保存するが、**これは実値を含むため絶対にコミットしない**（`.gitignore` 済み）。
既存の写像は常に優先される（後から辞書を作り直しても、前回と同じ架空値が維持される）。

## 実行手順

```bash
npx tsx tools/scrub/index.ts --in ~/squadbeyond-capture-quarantine --out capture/clean --names ~/known-names.txt --host-pattern '(?:https?://)?[a-z0-9-]+\.本番ホスト'
npx tsx tools/gate/grep-gate.ts --names ~/known-names.txt
```

**ゲートに1件でもヒットしたら土台化・コミットを止める**（企画書 §5-5）。

## grepゲートの検査項目

| ゲート | 企画書 | 内容 |
|---|---|---|
| 本番ドメイン | §13-F | 採取対象ホストの文字列が0件 |
| 外部SaaS | §13-G | Sentry / Pendo / HubSpot / GTM / GA4 / Mixpanel / Channel.io の識別子が0件 |
| 本番トークン | §5-5 | JWT / 32文字以上の不透明トークン / Bearerヘッダが0件 |
| 実金額らしい値 | §13-E | `¥〈金額の例〉` 形式の残骸が0件 |
| 実名 | §13-E | 既知社員名リストが0件（`--names` 指定時のみ） |
| gitトラッキング | §13-E | `scrub-map.json` / `.env` / 生キャプチャがgit管理下に無い |

## スキャン対象と除外（抜け道を作らないための明示）

**対象**: `capture` / `src` / `mock-server` / `tools` / `docs` / `tests` / リポジトリ直下

実名は成果物だけでなく手順書やテストのフィクスチャにも書かれるため、`docs` と `tests` も対象にしている
（当初は対象外にしていたが、実名がコミット済みでもゲートが合格を出していた）。

**除外**（`SELF_EXCLUDE`）と、その理由:

| 除外 | 理由 |
|---|---|
| `tools/gate/denylist.ts` | 検出パターンの定義元。検出語を持っているのが正しい |
| `tools/gate/grep-gate.ts` | 同上（ゲート実装本体） |
| `tools/scrub/policy.ts` | 外部SaaSタグの**除去**パターンの定義元。実行時にロードするコードではない |
| `dist/`（ディレクトリごと） | ビルド出力。`.gitignore` 済みでコミット対象ではない。中身は `src` と `capture` を束ねただけで両方とも走査済み → 検知力は落ちない。一方でミニファイ後の行番号で同じ違反がもう一度出るため、指摘が常時2倍になり本物が埋もれる。本番の dist は毎回ソースからビルドし直される |

**これ以外の除外を足すときは、必ずこの表に理由を残すこと。** 黙って除外を増やすのはゲートの無効化と同じ。

### 金額ゲートだけ走査範囲が狭い理由

`13-E 実金額らしい値` は `capture` / `docs` / `tests` だけを見る（`MONEY_SCAN_DIRS`）。

このゲートが探しているのは「**採取した実データ**の金額が消し残っていないか」。
自作のUI文言（離脱ポップアップのプリセット見本など）に出てくる価格まで拾うと、
LPビルダーである以上サンプルに価格が出るのは当たり前なので永久に赤くなる。
実名・実ID・本番ドメイン・本番トークンという**本当の漏洩経路**のゲートは、
引き続きスキャン対象の全域が対象（そちらは絞らない）。

### 二重計上の修正（2026-09-09）

`SCAN_DIRS` に `src` などの個別ディレクトリと `.`（直下）が両方入っており、
`.` を歩くと個別ディレクトリにも降りるため、全ファイルが2回走査されて
同じ違反が2件として数えられていた（「110件」の実体は55件）。
走査ファイル一覧を一意化して修正。件数が水増しされると、直したときにどれだけ減ったか読めない。

## 外部ホスト許可リスト（`EXTERNAL_HOST_ALLOWLIST`）

§13-F は「SquadBeyond本番バックエンドへ繋がないこと」を守るためのもの。
そこで、次の3種類だけを許可している。**足すときは必ずここに理由を書くこと。**

### 1. 規格上「絶対に実在しない」宛先

| 許可 | 理由 |
|---|---|
| `*.test` | RFC 6761 の予約TLD。DNSに存在しないことが規格で保証されている。匿名化後の架空ホストとSSRF防御テストの宛先がこれ |
| `*.example.com` / `.net` / `.org` | RFC 2606 の文書用予約ドメイン。UIの入力例・プレースホルダに使う |
| プライベート/予約IP | RFC 1918 / ループバック / リンクローカル / CGNAT / TEST-NET。公衆インターネットに出ない。**SSRF防御が「ここへは繋がせない」ことを確かめるテストの宛先**なので、検出するとテストを書くほどゲートが赤くなる |

いずれも末尾まで固定した正規表現で判定する。
予約ドメインを**前に付けただけ**の実在ホスト（`example.com.〈攻撃者のドメイン〉`）は通さない
（`tests/gate-scope.test.ts` に否定テストあり）。

### 2. ユーザーが明示的に依頼した外部連携（SB本番とは無関係）

| 許可 | 理由 |
|---|---|
| `graph.facebook.com` | Meta広告 実データ連携（指示⑤⑧）。env を入れたときだけ発信する |
| `slack.com` | Slack通知連携。OAuth と `chat.postMessage` |
| `api.chatwork.com` | Chatwork通知連携 |
| `developer.chatwork.com` | 上のAPI仕様を確認した先。コード内はコメントのリンクだけで発信しない |

### 3. 配信するLP／エディタが実行時に読むアセット

| 許可 | 理由 |
|---|---|
| `fonts.googleapis.com` | Webフォント。読み込まないとフォント指定が効かない |
| `code.jquery.com` / `cdn.jsdelivr.net` | ウィジェットが前提にしている外部ライブラリ（jQuery / Swiper / SmoothScroll / GLightbox）。読み込まないと内蔵JSが ReferenceError で動かない |

### 許可リストを広げた後の検証（2026-09-09）

「緑になったのは目を潰したからではない」ことを、偽の漏洩を仕込んで実測で確認した。
検知され exit 1 になったもの: 本番ドメイン / 許可外の外部ホスト（`api.openai.com`）/
Bearerトークン / 採取物内の `¥〈カンマ区切りの金額〉` / URL形の実ID（9文字）。
否定側は `tests/gate-scope.test.ts` に回帰テストとして固定してある。

**既知の限界**: grepベースなので、`'https://app.' + 'squad' + 'beyond.com'` のように
文字列を分割して書かれると検知できない（denylist.ts 自身がこの手を使って自己検知を避けている）。

## 実採取（2026-08-31）で強化した点

実DOMを通したことで、当初の「列挙式」の限界が判明した。以下を追加している。

| 追加した処理 | 理由（列挙式では漏れた） |
|---|---|
| **許可リスト以外の外部ホストを全て中和** | 顧客のLP配信ドメインはフォルダごとに異なり無数にある。個別列挙は必ず漏れる |
| **scheme無しの素のホスト名も中和** | `sb-xxx.example-domain.tokyo` のように本文に裸で出る |
| **SaaSタグを「内容を検査してから」除去** | script/noscript/link/iframe/コメント/空マウント要素の全形態に埋まっている |
| **SaaS識別子の残骸掃除** | GTMコンテナID・SaaSホスト名・CSSクラス名・URLパス内の名前が残る |
| **アセットのSPAフォールバック検出** | 存在しないパスにも200でHTMLが返るため「成功」判定が信用できない |

### 踏んだバグ（テストで検出・回帰テスト追加済み）

「SaaS識別子を含むタグを消す」を**1つの正規表現**で書いたところ、条件部がオプショナル扱いになり
**全ての `<script>` を消してしまった**。土台のスクリプトを巻き込むと再現が壊れる。
→ 「タグを拾う正規表現」と「中身の判定」を**分離**し、コールバックで内容を検査してから消す方式に変更。
回帰テスト4本（`tests/scrub.test.ts` の「回帰: SaaS除去が土台を巻き込まないこと」）で固定した。
