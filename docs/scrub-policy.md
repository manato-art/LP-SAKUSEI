# 匿名化ポリシー（scrub policy）

企画書 §5-5 が明文化を要求する「保持リスト / 置換リスト」の正本。
機械可読な実体は `tools/scrub/policy.ts`。本ファイルはその判断根拠を書く。

## 大原則

| | 内容 | 扱い |
|---|---|---|
| **保持（verbatim）** | 画面クローム / i18n文字列 ＝ ラベル・ボタン文言・空状態文・エラー文・バリデーション文言・テーブル見出し | **絶対に触らない**。忠実度の本体はここ |
| **置換** | ユーザー生成コンテンツ ＝ 施策名・beyondページ名・記事メモ・人名・金額/実績値・独自ドメイン・uid/トークン・メール/電話・アップロード物 | 決定論置換 |
| **除去** | 本番JSバンドル参照・外部SaaSタグ・Sentry DSN・inlineイベントの本番URL・meta等の個人情報 | 丸ごと削除 |

過剰scrubは忠実度を殺す。「日本語が架空値に化けたUI」は再現失敗である。

## 精度を出すための設計（重要）

DOM本文だけを見ても「この文字列がラベルか施策名か」は判別できない。
そこで **fixtures(JSON) のフィールド名を文脈として使う**:

1. fixtures を走査し、`title` / `name` / `memo` / `email` 等（`USER_DATA_FIELDS`）の**値**を置換辞書に集める
2. `status` / `role` / `icon_name` / `created_at` 等（`STRUCTURAL_FIELDS`）は辞書に入れない（列挙値を壊すと挙動再現が崩れる）
3. できた辞書の literal を DOM / CSS / HAR にも適用する

この順序により、「実際にユーザーデータとしてAPIが返した文字列」だけが置換され、
UIラベルは巻き込まれない。

補助として:
- 既知の実在社員名リスト（採取係が用意する**非コミット**ファイル。`--names` で渡す）
- パターン置換（メール / 電話 / Bearer / 32文字以上の不透明トークン / ホスト）

3文字未満の値は誤爆防止のため辞書に載せない。

## 参照整合

同じ実値は常に同じ架空値へ写す（`hashString` ベースの決定論生成）。
写像は `scrub-map.json` に保存するが、**これは実値を含むため絶対にコミットしない**（`.gitignore` 済み）。
既存の写像は常に優先される（後から辞書を作り直しても、前回と同じ架空値が維持される）。

## 実行手順

```bash
npx tsx tools/scrub/index.ts --in ~/squadbeyond-capture-quarantine --out capture/clean --names ~/known-names.txt --host-pattern '(?:https?://)?[a-z0-9-]+\.本番ホスト'
npx tsx tools/gate/grep-gate.ts --names ~/known-names.txt
```

**ゲートに1件でもヒットしたら土台化・コミットを止める**（企画書 §5-5）。

## grepゲートの検査項目

| ゲート | 企画書 | 内容 |
|---|---|---|
| 本番ドメイン | §13-F | 採取対象ホストの文字列が0件 |
| 外部SaaS | §13-G | Sentry / Pendo / HubSpot / GTM / GA4 / Mixpanel / Channel.io の識別子が0件 |
| 本番トークン | §5-5 | JWT / 32文字以上の不透明トークン / Bearerヘッダが0件 |
| 実金額らしい値 | §13-E | `¥1,234,567` 形式の残骸が0件 |
| 実名 | §13-E | 既知社員名リストが0件（`--names` 指定時のみ） |
| gitトラッキング | §13-E | `scrub-map.json` / `.env` / 生キャプチャがgit管理下に無い |

## スキャン対象と除外（抜け道を作らないための明示）

**対象**: `capture/clean` / `src` / `mock-server` / `tools` / `dist`

**除外**（`SELF_EXCLUDE`）と、その理由:

| 除外 | 理由 |
|---|---|
| `tools/gate/denylist.ts` | 検出パターンの定義元。検出語を持っているのが正しい |
| `tools/gate/grep-gate.ts` | 同上（ゲート実装本体） |
| `tools/scrub/policy.ts` | 外部SaaSタグの**除去**パターンの定義元。実行時にロードするコードではない |

`docs/` はスキャン対象外。企画書は再現対象を名指しする仕様書であり、
§13-E/F のスキャン範囲は「ビルド成果物・fixtures・ソース」だから（企画書 §13-E/F の文言どおり）。
**これ以外の除外を足すときは、必ずこの表に理由を残すこと。** 黙って除外を増やすのはゲートの無効化と同じ。
