# Widget編集（1つの画面）の決まり

2026-09-23 に「ノーコードで作る」（ライブラリの中の入力画面）と「Widget編集」（全画面）を1つにした（本人の決定 D1〜D3）。
この文書は、その画面の作り・保存の形・触るときの決まりの正本。詳しい理由は各ファイル先頭のコメントに書いてある。

## 画面の作り（widget-studio.ts）

全画面。**左＝見え方（620pxの見たまま画面）／右＝直すところ**。この左右は崩さない（本人指定）。

右は3段:

1. **画面のタブ**（`[data-widget-tabs]`）… 画面①②…
2. **部品** … 画面の設定／部品の一覧（選んだ1つを広げる）／部品を足す／Widget全体の設定（template-form.ts）
3. **デフォルト時のコードを表示** … Widget全体のHTML/CSS（widget-code-panel.ts）。直して「このコードで直す」で入れられる（2026-10-18・nocode/whole-code.ts）

ヘッダー: 閉じる／作成したWidgetに登録／**LPに入れる**（新しく作るとき）または **更新する**（LPの中のWidget）。

## 直し方は1つ（部品）— 2026-09-24 第3弾

本人の指摘「Widget編集とノーコードで作るで画面UIが2つある。ノーコードの方に合わせて、書式のツールバーだけは残して」。
以前あった「HTMLモード（要素ごとのカードとコードを右に出す）」は無くし、**どのWidgetも右は「部品」**。

| 開くもの | どう開くか |
|---|---|
| 部品で作ったWidget（外側に `data-nc-data`） | その設定データで開く |
| 設定データを持たないWidget（自作の見本・手書きのHTML・2026-09-23 より前の部品Widget） | `wrapHtmlAsBuilder`＝**見本の部品1つ**にして開く（余白0・背景「なし」で見え方は変えない）。部品が1つだけなら開いた直後にその部品を広げる |

見本の部品の中（form-sample.ts）に、以前のWidget編集にあった直し方を全部置いた:
- 文字・画像・動画・ボタン・囲み の欄と「押したとき」、設問①②…のタブ（前からあるもの）
- **見た目の細かい設定** ＝ 要素ごとのカード（widget-design-panel.ts。色・大きさ・余白・動き。数字はドラッグ＋スライダー）
- **コードで直す** ＝ この見本のHTML・CSS（色付きのコード欄。打ち終わると入力欄を組み立て直す）

左の見たまま画面:
- **書式のツールバーは常に出す**（太字・色・大きさ・フォント・リンク・画像…）。見出し・文章・ボタンなどの部品の文字も、ツールバーで付けた飾りごと持つ（`rich-text.ts`。持てるのは文字の飾りだけ＝b/i/u/s/span/font/br と色・大きさの style。script・img・a などは外す）
- 見本の部品の中を押すと、右でその部品が開き「見た目の細かい設定」がその要素のカードだけになる。左の枠もその要素に付く
- 画像の操作パネル・リンクの吹き出し・並んだ部品の複製/上下/消す は**見本の部品の中だけ**効く（見出しやボタンの部品は右の欄で直す）
- 道具が中身を変えたら `notifyCanvasEdit(contentDiv, 変えた要素)`（widget-canvas-events.ts）で知らせ、その要素の部品だけ設定データへ読み戻す
- Widget全体の上下の余白は「Widget全体の設定」か、何も選んでいないときの枠の上下の辺で
- 「デフォルト時のコードを表示」はWidget全体のコード。直して「このコードで直す」を押すと、全体が「コードの部品」（見本の部品）1つになる（確かめてから・「戻す」で戻せる）。もう「コードの部品」1つだけなら、その部品のコードを出して差し替える（入れ子にしない）

## 保存の形（builder-data.ts）

```html
<style>…</style>
<div class="nc nc-builder nc-xxxxxxxx" data-nocode="builder" data-nc-data="{…JSON…}" data-nc-screens="true" …>…</div>
<script>…</script>
```

- `data-nc-data` は `TemplateData` を JSON にして属性にしたもの（`& " < >` はエスケープ）。読むときは戻す
- 画像・動画は data URL のまま JSON に入る。保存のとき本文と同じ規則で別ファイル（`/uploads/<ハッシュ>.<拡張子>`）に置き換わるので、
  開き直したときは `/uploads/…` の形になる。`kit.ts` の `safeImage` / `safeVideo` はこの形も受け付ける
- 見本の部品の中身（html）もそのまま JSON に入る
- 「部品を解除」のボタンは無い（第3弾で HTMLモードを無くした）。コードを直したいときは、見本の部品の「コードで直す」か、全体のコード欄の「このコードで直す」（2026-10-18 本人の選択「全体のコードを直す」）
- 部品の一覧の「全部消して作り直す」で白紙に戻せる（Widget全体の設定はそのまま）。白紙になると「何から作りますか？」がまた出る

## 触るときの決まり

- 左の見たまま画面の中身（contentDiv）は保存しない（保存は設定データからの書き出し）ので、編集専用の目印を付けてよい。
  ただし見本の部品の中身は DOM から読み戻す（innerHTML）ので、見本の中には目印を付けない（KB 2026-09-22-001）
- 選択枠・操作ボタンは contentDiv の**外の層**に置く（selection-layer.ts・item-toolbar.ts）
- 左の文字を打ち直したときは、その部品だけ読み戻す（`syncCanvasBlock`）。部品をまたぐ入力・打てない部品への入力は `beforeinput` で止める
- 部品の数え方は「画面をまたいで上から順の通し番号」（`nc-b-12`）。書き出し（builder.ts）と読み戻し（`blockPathAt`）で同じ数え方にする
- テストは純粋ロジックに切り出して vitest で固定する（builder-data・canvas-sync は linkedom）。画面そのものはブラウザで確かめる
- スマホは `mobile-css.ts` の `[data-widget-*]`（左右→上下）と `[data-nc-tab]`（入力欄の大きさ）がそのまま効く

## Canva 風の直接操作（第2弾・2026-09-23）

- **選択枠のつまみ**（selection-layer.ts）: 右の辺＝幅、下の辺＝高さ、右下の角＝文字の大きさ、上下の辺＝Widget全体の上下の余白。
  動かしている間は見た目だけ（`preview`）、離したら確定（`commit`）。値の計算は drag-math.ts（`dragValue`）
  - 部品: 画像・図形＝幅%、余白＝高さpx、見出し・文章＝文字の大きさpx、何も選んでいないとき＝Widget全体（上下の余白）。確定で設定データへ書いて描き直す
  - 見本の部品の中の要素: そのカードにある `width`/`height`/`font-size`（CSS変数は名前で見分ける `handleKindOf`）。画像・動画は幅%の直書き
- **数字の欄**（number-scrub.ts）: 名前や単位を左右にドラッグで増減（4pxで1刻み）＋下にスライダー（範囲は `sliderRange`）。部品の入力欄（form-controls.ts）と要素ごとのカード（widget-design-panel.ts）の両方
- **部品の並べ替え**: 右の一覧の頭をつかんでドラッグ（上半分に落とすと前、下半分で後ろ。`moveTo`）
- 見本の部品の「見た目の細かい設定」は、**左で押した要素のカードだけ**を出す。「全部のカードを見る」で一覧
- 大きさの選び（見出し 大/中/小・文章 標準/小さめ・余白 小/中/大・上下の余白 狭い/普通/広い）は**数（px）**に変えた。古い中身の文字（'l' など）は `legacy` の表で読み替える（`sizeOf`・number欄の `legacy`）

## 部品の幅と置く位置（2026-09-24）

本人「動画もサイズ調整。どの部品も中央揃え・左右へ・サイズを変えられるように。ツールバーからも、選んだら必ず、枠にカーソルを当ててシームレスに動かせるように」。

- **どの部品も**（余白以外）右の欄のいちばん上に「幅（10〜100%）」と「置く位置（左・中央・右の絵）」。幅の欄の名前は部品ごとに違う（`widthKeyOf`: 画像・動画＝width、図形＝size、ほか＝boxWidth）
- 書き出し（`layoutCss`）: 画像・動画は中の絵、図形はそれ自体、ほかは外枠に `width` と左右の `margin`。外枠に効かせる部品は幅100%なら何も書かない（見本の左右いっぱいを変えない）
- 見出し・文章の「文字の寄せ」に右を足した（置く位置とは別。文字の並びの寄せ）
- 左の見たまま画面（selection-layer.ts）
  - **マウスを乗せる**と薄い点線の枠と名前（どれを触るか押す前に分かる）
  - **幅のつまみ**: 右の辺（右に置いた部品は左の辺）。中央に置いた部品は両側へ広がるので手の動きの2倍で幅が変わる
  - **つかみ所**（枠の上のまん中の十字）: つかんで左右＝置く位置、上下＝並び順（入る所に青い線）。部品は手について動く（補助線の節）
  - 画像・動画・図形・余白・区切り線・型の部品は、**部品そのものをつかんで**も動かせる（5px動いてから動き出す。離した直後の click は選び直しに使わない）
- 上のツールバー: 「配置 ⌄」＝左・中央・右を選ぶ小窓（align-menu.ts。見出し・文章は文字の寄せ、ほかは置く位置、今の値は青。見本の中・何も選んでいないときは選んだ文字の寄せ＝両端そろえも）。「サイズ」＝選んだ部品の幅と置く位置の小窓（size-popover.ts）。見本の中・何も選んでいないときは今までどおりの動き
- ⚠️ 動かしている間だけ要素に直に当てた見た目（幅・余白など）は、描き直すたびに必ず外す（`clearPreviews`）。CSSだけの変化では要素を入れ替えないので、外さないと古い見た目が勝ち続ける

## 補助線と吸い付き（2026-09-24）

本人「補助線もやって」（手で動かしたとき、どこへ収まるかが事前に見えるように）。計算は drag-math.ts（DOMなし・tests/drag-math.test.ts）、線と影は selection-layer.ts。

- **部品を動かす**: 部品は手についてそのまま動く（見た目だけ `transform: translate`）。左・中央・右に 8px（`SNAP_PX`）まで近づくと吸い付き、**ピンクの縦線**（左の端・まん中・右の端）。吸い付いていないときは、離したら収まる所（一番近い位置）を**点線の影**で見せる。離すと設定データの `place` に書く（保存できるのは3つだけなので、途中の位置には止まらない）
  - 幅が100%の部品は横に動かない。並び順は**動かしている部品の真ん中**がほかの部品の真ん中を越えたかで決める（手の位置で見ると、つかみ所が部品の上の辺にあるので、上の部品が低いと動かす前から「ここへ移す」になった）
  - 並びを変えるときは影を出さない（入る所は青い線で見せる）
- **幅のつまみ**: ほかの部品の左右の端に辺がそろう幅と、よく使う幅（25・50・75・100%）に吸い付き、自分の辺（中央に置いた部品は両側）にピンクの縦線。吸い付き先は動かし始めたときに1回だけ測る（`SelectionHandle.snaps`）
- 幅%の基準は親の中身（padding の内側・`contentBoxOf`）。つまみの手の動きの換算もこれに合わせた
- **Alt（Mac は option）を押しながら**動かすと吸い付かない（`snapThreshold(true)`＝0。本人「やる」2026-09-24）。50%のすぐ隣の49%などをつまみで作るため。ぴったり重なったときだけ線は出る。案内はつかみ所・幅のつまみの title
- 線・影は動かし終わったら selection-layer が必ず消す。`transform` も `clearPreviews` の対象

## ダーク表示（2026-09-24・本人の決定「周りだけ暗く・Widgetは白」）

周り（ヘッダー・地・右の欄・書式ツールバー・小窓）はアプリの他の画面と同じ規則で暗くし、まん中の見たまま画面（LPに入る中身）は配信されるLPと同じ白地・黒い文字のまま。ライトの見た目は変えていない（ライトで Widget編集の全要素の色・枠・影・大きさを変更前と突き合わせて一致）。

- 周りのインラインstyleの色は `var(--sb-c-xxxxxx, #元の色)`（定義は src/index.html。ダークの値は src/shared/dark-color.ts と同じ規則）。注入した `<style>`（ツールバー・右の欄・仕切り）は dark-runtime-css.ts が自動で暗くする
- 見たまま画面: LPの枠は地を透かして 620px の箱を白い紙にする（`frameStyle`）。ポップアップの枠の地（離脱防止＝灰色・追従型の角＝白）は配信の見え方なのでダークでも変えない
- ⚠️ プレビューのCSSとWidget自身の `<style>` は、`data-dark-runtime="skip"`（styleTag と contentDiv に付ける。祖先に付いていても効く `isRuntimeDarkSkipped`）で実行時の上書きの対象から外す。外さないと Widget の白い地が黒く塗られる
- ⚠️ contentDiv には `color:#000;color-scheme:light`。ダークの html は `color-scheme:dark` なので、何もしないと Widget の文字（色の指定が無いところ）が白くなって白い紙に消える
- 選んだ行・タイルの地 `--sb-accent-tint` は、ダークでは theme-color.ts の `darkTint`（ライト用の薄い地を同じ規則で暗くしたもの）。ライト用の薄い青のままだと明るくなった文字が読めなかった。右の欄の赤い文字（消す・エラー・全部消して作り直す）はダークだけ #FF8A7A（nocode-form-css.ts）
- ダークでも白のままでよいもの: 選択枠のつまみ・つかみ所（白い紙の上）、「デフォルト時のコードを表示」のスイッチのつまみ、色見本（実際の色）
- 確かめ方: ブラウザで、周りの全要素について文字と地のコントラスト比を計算して 3 未満が無いこと、プレビューの中の全要素の色がライトとダークで同じこと（tests/widget-studio-dark.test.ts はソースで固定）

## ポップアップの中身もこの画面で（2026-09-24）

本人「離脱防止ポップも同じ感じで簡単に。画面が色々あると分かりづらいから、Widget編集と同じ画面を移植」。決定: **中身だけWidget編集で**（名前・配信・表示条件・位置・出し分けの画面はそのまま）・**追従型も同じ**。

- 入口: ポップアップの編集画面の左上＝今の中身の小さな絵（iframe・スクリプトは動かさない）＋「中身を編集」（popup-content-card.ts）。一覧のカードの絵も今の中身（以前はプリセットの絵のまま＝直した中身が一覧に出なかった）
- 画面の組み立ては `mountStudio`（widget-studio.ts）で LPのWidget と共通。ポップアップ用は popup-studio.ts の `openPopupStudio`: 右上＝「ポップアップに反映」（書き出したHTMLを保存・保存できたら閉じる）
- 見たまま画面の枠（`PreviewFrame`）: 離脱防止＝`overlay`（灰色の地＝配信の暗幕、最大500pxで中身の幅の箱＝配信の .ep-content）／追従型の上下の帯＝`lp`（620px）／追従型の角＝`corner`（中身の幅）
- 始まり（popup-studio-start.ts・DOMなし）: 空＝白紙／設定データつき＝そのまま／プリセット・手書き＝見本の部品1つ（追従型の CSS も中の `<style>` へ。保存したら CSS の欄は空にする＝二重に効かない）
- ライブラリの見本・作成したWidget・お気に入りも部品に入れられる（2026-09-24 本人「やって」）。ポップアップの画面にはLPの編集＝Quill が無いので、ライブラリは `openWidgetLibraryForPick(null, …)`＝**見本を選ぶだけ**で開く: 「+ Widgetを作成」「+ ノーコードで作る」「画面を作って使う」（LPへ入れる入口）は出さない。「追加」は必ず部品として渡る
- 消したもの: 離脱防止の「デザイン」タブ（要素ごとのカード＝見本の部品の「見た目の細かい設定」に同じものがある）と、HTMLの欄。「コード」タブに JavaScript・HeadTag・BodyTag（追従型は CSS・JavaScript）だけ残した
- 設定画面の「プレビュー」（離脱防止 `previewPopup`・追従型 `previewFollowPopup`）も、画面に載せてから中身の `<script>` を動かす（`runWidgetScripts`。innerHTML では動かず「次へ」で画面②へ移れなかった）。順番は配信と同じ＝中身のスクリプト→ポップアップの JavaScript。小さな絵は `<script>` を外して描く（`thumbnailHtml`。絵の iframe はスクリプトを動かさないので、残すとエラーが出続ける）
- ⚠️ 配信（delivery-popup-html.ts）: 中身の `[data-nc-go]`（部品で作った「次の画面へ」）を押したときは、ポップアップの「LPに戻る＝閉じる」「遷移先へ移動」より先に抜ける（入れる前は、画面①→②で閉じてしまった）
