# サブエージェント共通指示（第2ラウンド）

作業を始める前に **必ずこのファイルを全部読む**。ここに書いていない前提を自分で作らない。

## 1. 絶対ルール（破ったら成果物は破棄）

1. **本番アプリに一切アクセスしない。** ブラウザで `*.squadbeyond.com` を開かない。
   採取はすべて完了済み。あなたが見るのはローカルの採取済みファイルだけ。
2. **実データを持ち込まない。** 人名・企業名・実LPのURL・実際の金額をコードに書かない。
   採取済みファイルは匿名化済み。そこから読み取った値をさらに別ファイルへ**転記しない**。
3. **`package.json` を編集しない。** 依存を足したくなったら、足さずに報告する。
4. **`~/squadbeyond-capture-quarantine/` の中身をコミットしない・リポジトリへコピーしない。**
   読むのは可。読んだ生データをそのまま `src/` へ貼らない（`capture/clean/` 経由の断片だけ使う）。
5. **推測で埋めない。** 採取物に無い情報は「無い」と報告する。それらしく作らない。
   デザインを手書きのCSSで似せない（企画書 §5: capture-and-rehydrate）。

## 2. 手法（これ以外の方法を取らない）

**採取した実物のHTMLを土台にして、挙動だけローカルのモックへ配線する。**

- 見た目のマークアップは `src/app/fragments/*.html` から**そのまま**取り出して使う。
- クラス名は Emotion が生成した実物（`css-xxxxxx`）。**改名しない・自作しない。**
- 配線のフックは `data-test` 属性。無ければ Emotion クラス名か、
  DOM構造（`nth-child` など）で特定する。**新しい `data-test` を実物に足さない。**
- CSSは `capture/cssom.css` と `capture/css/` に採取済み。**CSSを書き足さない。**
  どうしても必要なら理由を報告して指示を待つ。

## 4. コーディング規約（ユーザーの全プロジェクト共通ルール）

- **不変更新**。既存オブジェクトを書き換えない。必ず新しいオブジェクトを返す。
- 1ファイル **200〜400行が普通・800行が上限**。超えるなら分割する。
- 命名: 変数/関数 `camelCase` / 真偽値は `is`/`has`/`should`/`can` 接頭辞 /
  型・コンポーネント `PascalCase` / 定数 `UPPER_SNAKE_CASE`。
- エラーは握りつぶさない。境界で検証する。
- **UIに絵文字を使わない**（アイコンはSVG）。**AIモデル名をUI文言に出さない**。
- **左右の余白を足さない**（エッジtoエッジ）。採取物の余白をそのまま使う。

## 5. テスト（TDD必須）

- **先に落ちるテストを1本書き、赤を確認してから実装する。**
- Vitest。環境は node（jsdomは無い）。DOMを直接触るテストは書けない。
  → **純粋関数に切り出して**テストする（例: 「この入力から何のリクエストを作るか」）。
- 既存テストを壊さない。

## 6. 完了報告の作法（最重要）

**「できた」と言う前に、実際に走らせて緑を確認する。**

```bash
npm run typecheck && npm run lint && npm test
```

報告には必ず次を含める:

1. **実際に走らせたコマンドと、その出力の要点**（件数など）。走らせていないなら走らせていないと書く。
2. **できなかったこと・採取物に無くて推測した箇所の一覧。**
   ここを正直に書くことが最も価値が高い。埋めた風にして黙るのが最悪。
3. 触ったファイルの一覧。

評価チームから差し戻しが来たら、それに答えること。
